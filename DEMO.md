# Actual recording plan

This is a plan for a short live demonstration, not an existing video. Record the
real browser UI at its native resolution. Do not upscale a low-resolution crop.
Keep labels legible, use a pointer only to indicate actual actions, and add captions.

Suggested length: 1 minute 45 seconds to 2 minutes 15 seconds. Hyperbloom's currently
published overview does not impose a video duration; recheck the actual form.

1. **0:00–0:15 — Show the job.** Show the actual workbench with the illustrative
   ecology deck. Say that this is a print-preparation tool for paired study cards.
   State that the example content is illustrative.
2. **0:15–0:40 — Make a change.** Edit one answer through the list, save it, then add
   a ninth card. Show the partial second sheet and return to the first.
3. **0:40–1:05 — Show the difference.** Select Answers. Explain why columns exchange
   positions for long-edge printing. Change to short edge and show the row change.
   Do not imply that this is a recording of a physical printer.
4. **1:05–1:30 — Finish the job.** Select Prepare to print, show the preflight and
   download the actual HTML print file. Open that file and show the paired pages.
   Show the numbered alignment test and the exact print settings.
5. **1:30–1:50 — Show a boundary.** Add a card with many line breaks, return to
   preflight and show the blocked overflow result. Then explain the local storage,
   editable JSON copy, and physical printer limitation.
6. **Closing — Keep the claim narrow.** “Turnside makes the pairing visible before
   printing. The digital layout is tested; printer alignment needs a test sheet.”

Use a fresh example deck before recording. Restore it through the UI using Start
fresh → Load example deck. The download is generated by the app; never replace it
with a manually composed mockup. A test-only ninth card can read:

Question: What makes a paired print useful?
Answer: The answer sits behind its question when the sheet turns on the chosen edge.

The final video, hosted links, commit and submission receipt belong in the parent's
submission manifest after they actually exist. QA screenshots are not a video.
